## 三、手工部署顺序

```bash
createdb diet_agent
pg_restore --no-owner --no-privileges --exit-on-error -d diet_agent 01_完整数据库备份_diet_agent_v1.2r2_合并版.dump
psql -d diet_agent -v ON_ERROR_STOP=1 -f 12_数据库整改_v1.2_to_v1.2r1.sql
psql -d diet_agent -v ON_ERROR_STOP=1 -f 03_应用账号与权限.sql
psql -d diet_agent -v ON_ERROR_STOP=1 -f 18_病种字典补齐_v1.2r1.sql
psql -d diet_agent -v ON_ERROR_STOP=1 -f 14_RAG向量化_v1.2r1.sql
psql -d diet_agent -v ON_ERROR_STOP=1 -f 19_知识库主题扩充_v1.2r1.sql
psql -d diet_agent -v ON_ERROR_STOP=1 -f 20_数据补充_铁源纤维钙_v1.2r2.sql
psql -d diet_agent -v ON_ERROR_STOP=1 -f 21_反向营养映射_待审核_v1.2r2.sql
psql -d diet_agent -v ON_ERROR_STOP=1 -f 04_数据库整体验收.sql
psql -d diet_agent -v ON_ERROR_STOP=1 -f 22_数据补充验收_v1.2r2.sql
```

`14` 需要数据库实例已安装 pgvector。如果本机没有 pgvector，可先跳过 14 和向量灌库，但其余结构和数据仍可验收。正式部署建议使用 `docker/`。

## 四、Docker 部署

在交付包根目录执行：

```bash
docker build -f docker/Dockerfile -t diet-agent-pg:1.2r2 .
cd docker
POSTGRES_PASSWORD=你的密码 docker compose up -d
docker compose logs -f db
```

初始化顺序为：

```text
00 前置校验 → 10 恢复备份 → 20 数据库整改 → 30 权限 → 40 病种
→ 50 pgvector → 55 知识库 → 56 铁/纤维/钙 → 57 反向营养 → 60 汇总验收
```

向量结构会随容器初始化建立，但真实向量仍需在容器启动后按 `16_RAG对齐与灌库说明.md` 执行 `15_RAG灌库脚本.py`。

## 五、数据口径

- 食材营养数据按每 100 g 可食部记录，菜式按配料克数汇总；
- 本次补充的纤维以及部分钙来自公开同类食材数据，一级 `data_quality` 采用保守的 `approx`，具体来源保留在 `source_row.supplemental_nutrients`；
- 菜式纤维和钙为估算结果，没有计算烹饪损耗；
- 反向营养映射只表达“可能相关”和“建议关注”，不能用于诊断；
- 反向营养映射在专业审核前保持 `review_status=pending`、`is_reviewed=false`、`is_active=false`。
