## 六、`\restrict` 这一行是什么

`02_数据库结构_diet_agent_v1.2.sql` 第 5 行是：

```
\restrict u0dyDwn1ff3XA00MRSdm9c8KbDOzk3mSgAfZ3M3t8fdZ9ar65j4SEiFyQIsfRGk
```

这是 **PostgreSQL 18 的 pg_dump 自动写入的会话保护元命令**，不是数据、不是表结构、也不是我们加的东西。
机制：pg_dump 18 在输出开头写一条 `\restrict <随机令牌>`，在结尾写配对的 `\unrestrict <同一令牌>`
（本文件两处 `restrict` 就是这个配对）。在这段"受限区间"内，psql 会拒绝执行 `\!`（调用 shell）之类的
危险元命令，目的是防止有人把备份文件当成可信脚本执行时被注入。

对本包的影响：

- 用 **psql 18** 执行 02：正常，psql 认这两条命令，自动进入/退出受限态。
- 用 **psql 17 及更早**执行 02：会各自报一行 `invalid command \restrict` /
  `invalid command \unrestrict`，然后继续往下执行 SQL（这些 SQL 本身不依赖它）。
  但如果脚本前加了 `-v ON_ERROR_STOP=1`，psql 会因为这两行直接退出——这会被误判成"结构脚本坏了"。
- 01 dump 的头部同样带 `PGDMP` 与归档版本 1.16，那是另一回事（归档格式，不是元命令）。

所以建议：**执行 02 用 psql 18**；若手上只有旧版 psql，就用 `psql -f 02...`（不加 ON_ERROR_STOP），
或直接用 pg_restore 走 01（结构+数据一次到位，也不需要 02）。本轮 12 与 04 是我自己写的，
没有 `\restrict`，不受此影响。
