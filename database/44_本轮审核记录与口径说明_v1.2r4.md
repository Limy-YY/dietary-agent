本文件记录两件事的审核结论、依据与验收口径：

1. **反向营养映射**：16 条待审核 → 审核后 13 条 → 本轮激活并补 6 条高频症状 = **19 条上线**（`41` 号脚本）；
2. **疾病规则口径**：高血压钠目标互斥收敛 + 糖尿病/痛风/高血脂落地 = **9 条规则审核启用、7 条生效**（`42` 号脚本）。

对应验收脚本：`43_审核激活验收_v1.2r4.sql`。

> **审核人签署**：本轮的规则文本、证据分级与口径结论由数据岗复核并落库，`reviewer` 字段默认写
> `数据岗审核（AI 辅助复核，待责任医师签认）`。正式签认时用 `-v reviewer='姓名（资质）'` 覆盖，
> 或在 `core.symptom_nutrient_map.reviewer` / `audit.condition_rule_review.reviewer_name` 上更新。

## 一、反向营养：16 → 13 → 19

### 1.1 为什么不是把 16 条原样激活

`37_21号反向营养映射审核修订说明.md` 已经给出专业审核结论，本轮**沿用**该结论，不推翻：

| 原 16 条 | 处理 | 原因 |
| --- | --- | --- |
| 容易疲劳 / 身体无力（各映射铁） | 合并为「容易疲劳」，`身体无力` 进别名 | 两条语义接近，子串命中会重复召回同一营养素 |
| 容易骨折（钙） | 删除 | 骨折是临床结局，不能直接归因缺钙 |
| 记忆力下降（B1） | 删除 | 一般记忆力下降不能指向 B1 缺乏 |
| 舌头肿痛（B6） | 主映射改 B2，说明提示铁/B12/叶酸 | 舌炎不是 B6 特异表现 |
| 16 条统一 moderate | 逐条分级 | 避免证据等级虚高 |

因此「16 条审核激活」的落地口径是：**清掉 3 类旧稿残留 → 按审核文本激活 13 条 → 补 6 条高频症状）**。
`41` 号脚本对两种起点都幂等：已跑过 `21`（13 条 pending）或只恢复 `01` 备份（原 16 条 pending）都会收敛到同一结果。

### 1.2 本轮新增的 6 条高频症状（IMP-038）

| 症状 | 别名 | 营养素 | 证据 | 依据 |
| --- | --- | --- | --- | --- |
| 掉发 | 脱发、掉头发、头发掉得多、发量减少 | 铁 | low | NIH ODS Iron；脱发原因多，仅部分与缺铁相关 |
| 便秘 | 排便困难、大便干结、排便不畅 | 膳食纤维 | moderate | 《中国居民膳食指南（2022）》膳食纤维与蔬果全谷物原则 |
| 失眠 | 睡不着、入睡困难、睡眠差、容易醒 | 镁 | low | NIH ODS Magnesium；镁与睡眠证据有限，已写明不建议自行长期补镁 |
| 腿抽筋 | 小腿抽筋、夜里抽筋、肌肉痉挛 | 钙 | low | NIH ODS Calcium；电解质/受凉/药物/血管神经因素并列 |
| 口腔溃疡反复 | 口腔溃疡、口疮、嘴里起泡 | 维生素B2 | low | NIH ODS Riboflavin；B2/铁/锌/B12/叶酸并列，两周不愈转诊 |
| 皮肤干燥 | 皮肤干、皮肤粗糙、起皮 | 维生素A | low | NIH ODS Vitamin A；写明勿自行大剂量补 A（蓄积毒性） |

新增目的：解决 IMP-038 记录的实测场景——用户输入「乏力 掉发」时，原来只命中「乏力→铁」，
「掉发」完全查不到；现在两条都能命中（`43` 号验收里有这条断言）。

### 1.3 分级与覆盖

- 19 条 = moderate **8** 条 + low **11** 条，**没有 strong**：症状→营养素只能作线索；
- 7 种关键微量（钙/铁/锌/VA/B1/B2/VC）**7/7 覆盖**，另外新增镁与膳食纤维两条营养素线；
- 每条都带 `source_id`（NIH ODS 或《中国居民膳食指南（2022）》）与 `reviewer`/`reviewed_at`；
- 所有说明文本保持「可能 / 建议关注 / 建议就医」措辞，不含诊断结论。

### 1.4 对后端的影响

`backend/app/routers/agent.py` 的 `_search_symptom_map()` 只取 `is_active=true`，
本轮激活后 `POST /api/agent/reverse-nutrition` 的 `method` 会从 `keyword_fallback` 变为 **`symptom_map`**。
`docs/testing/联调回归清单.md` 里 L-04 的判据（原先按「16 条全未激活」锁定 `keyword_fallback`）已同步改写，
否则会把正确行为判成 FAIL。

## 二、疾病规则口径审核

### 2.1 审核发现的 4 个口径问题

| # | 问题 | 事实依据 | 本轮处理 |
| --- | --- | --- | --- |
| 1 | **钠目标三条并行** | `HTN-SODIUM-WHO-NHC-2000`（<2000mg）、`HTN-SODIUM-DASH-2300`（<=2300mg）、`HTN-SODIUM-DASH-1500`（<=1500mg）同时 `approved` 会对同一用户给出三个"上限"，规则引擎无法判定按哪条 | 设 `mutually_exclusive_group=hypertension_sodium_target`，**只保留 2000mg 为生产默认生效**；另两条 approved 但 `is_active=false`，仅个人方案/医生指定时用 profile 覆盖打开 |
| 2 | **模式规则没有数值语义** | `app.preview/evaluate_daily_condition_nutrient_rule` 只处理 `nutrient_limit`/`nutrient_target`；`HTN-PATTERN-DASH` 是 `pattern_preference` | DASH 模式规则保持 `approved + is_active=true`，但显式 `numeric_evaluation=false`、`advisory_only=true`，只在目录/提示层使用 |
| 3 | **糖尿病/痛风/高血脂无法做阈值** | `core.nutrient` 只有微量与钠钾，**没有 carbohydrate / added_sugar / saturated_fat / purine**；`app.nutrition_result.computed` 也没有 `sugar_g` / `purine_mg`；嘌呤只存在 `core.ingredient.purine_level` | 三个病种落成 `pattern_preference`（偏好）与 `review_gate`（人工闸门），并在 `evaluator.numeric_blocker` 写明缺什么，**不造"永远 not_evaluable"的假规则** |
| 4 | **激活可绕过审核** | `audit.condition_rule_review` 是审批留痕表，只改 `is_active` 不会留下记录 | 9 条规则全部写入 `approved` 审批记录（含 reviewer/role/note），`43` 号验收断言"生效规则必须有 approved 记录" |

### 2.2 最终规则清单（9 条）

| rule_id | 病种 | 类型 | 生效 | 说明 |
| --- | --- | --- | --- | --- |
| HTN-SODIUM-WHO-NHC-2000 | 高血压 | nutrient_limit | ✅ | 唯一生产钠目标：<2000mg/日（WHO 2g；对应食盐 5g 以下） |
| HTN-SODIUM-DASH-2300 | 高血压 | nutrient_limit | ⛔ | 互斥候选：DASH 2300mg，需个人方案/医生指定 |
| HTN-SODIUM-DASH-1500 | 高血压 | nutrient_target | ⛔ | 互斥候选：DASH 严格档 1500mg |
| HTN-PATTERN-DASH | 高血压 | pattern_preference | ✅ | DASH 模式（减钠增钾）；不参与数值判定 |
| DM-PATTERN-LOW-GI | 糖尿病 | pattern_preference | ✅ | 全谷物低 GI、限添加糖与精制米面 |
| DM-ADDED-SUGAR-GATE | 糖尿病 | review_gate | ✅ | 高添加糖菜品进方案需人工确认 |
| GOUT-PATTERN-LOW-PURINE | 痛风/高尿酸 | pattern_preference | ✅ | 限高嘌呤、控果糖与酒、足量饮水 |
| GOUT-HIGH-PURINE-GATE | 痛风/高尿酸 | review_gate | ✅ | 高嘌呤食材默认排除，确需出现须确认 |
| HLP-PATTERN-LOW-SATFAT | 高血脂 | pattern_preference | ✅ | 限饱和脂肪、增膳食纤维 |

来源：WHO 钠指南、NHLBI DASH、国家卫健委《成人高血压/糖尿病/高脂血症食养指南（2023 年版）》、
《成人高尿酸血症与痛风食养指南（2024 年版）》（官方发布页为 `chinacdc.cn` 与 `chinanutri.cn` 的通知原文），
以及 DRIs 2023。每条规则在 `core.condition_rule_source` 至少有 1 条来源映射。

### 2.3 口径边界（本轮**没有**做的事）

1. **疾病规则尚未接入候选硬约束**：`backend/app/services/rule_engine/candidates.py` 的硬排除仍只有
   「过敏原 / 宗教忌口 / 显式排除食材 / 厨具」四类，`targets.py` 把 `confirmed_conditions` 写进
   `condition_note` 仅作提示。本轮只完成**数据侧口径与启用**，候选构造阶段的接入属 IMP-041 后半段（后端 P1）。
2. **糖尿病/痛风/高血脂的数值判定仍缺数据底座**：要做数值达标判断，需要先补
   `core.nutrient` 的 carbohydrate / added_sugar / saturated_fat / purine 行，并在
   `app.nutrition_result.computed` 里落 `sugar_g` / `sat_fat_g` / `purine_mg` 聚合，再改 `preview/evaluate` 的取值口径。
   在此之前，`pattern_preference` 与 `review_gate` 是**诚实**的上限，不是偷懒。
3. **`app.v_production_condition_rules` 会从 0 条变成 7 条**：后端
   `backend/app/routers/conditions.py` 与 `openapi.json` 里"当前正式规则 0 条"的描述已同步修改；
   前端/测试若写死"正式规则为 0 条"的判断需要跟着改。
4. **未动 `01` 备份**：`01` 里的 16 条旧映射与 4 条 pending 规则保持原样，恢复后按顺序跑 `21 → 41 → 42` 即可。

## 三、复跑与回滚

### 3.1 复跑顺序

```bash
psql -d diet_agent -v ON_ERROR_STOP=1 -f 41_反向营养映射审核激活_v1.2r4.sql
psql -d diet_agent -v ON_ERROR_STOP=1 -f 42_疾病规则口径审核_v1.2r4.sql
psql -d diet_agent -v ON_ERROR_STOP=1 -f 43_审核激活验收_v1.2r4.sql
```

`41`、`42` 均幂等：重复执行不会新增重复映射/规则/来源/审批记录，`reviewed_at` 也不会被刷新。
正式签认时加 `-v reviewer='姓名（资质）'`。

### 3.2 回滚

```sql
-- 反向营养：回到待审核（不影响其它批次）
UPDATE core.symptom_nutrient_map
   SET review_status = 'pending', is_reviewed = false, is_active = false,
       reviewer = NULL, reviewed_at = NULL
 WHERE nutrient_id IN ('iron','vitamin_a','vitamin_c','vitamin_b2','vitamin_b1','zinc','calcium',
                       'dietary_fiber','magnesium')
   AND review_status = 'approved';

-- 疾病规则：DASH 两条与新增五条退出生产，只留钠 2000mg 与 DASH 模式
UPDATE core.condition_nutrient_rule
   SET is_active = false
 WHERE rule_id <> 'HTN-SODIUM-WHO-NHC-2000';
```
