# 空库恢复与复跑说明（v1.2r4，合并版）

## 恢复方式

目标 PostgreSQL 需要安装 pgvector。推荐使用本包 `docker/`，也可以在已经安装 pgvector 的 PostgreSQL 18 中执行：

```bash
createdb diet_agent
pg_restore --no-owner --no-privileges --exit-on-error \
  -d diet_agent 01_完整数据库备份_diet_agent_v1.2r2_合并版.dump
```

这份备份是 v1.2r2 基线（60 道菜 / 128 种食材），包含审核前的 16 条反向营养映射。恢复后按 07 第三节顺序继续执行：12 整改 → 03 权限 → 18 病种 → 38 菜式扩充（60→120）→ 39 过敏原复核 → 14 向量结构 → 19 知识库主题 → 20 铁/纤维/钙补充 → 21 反向营养映射（21 会删除仍处于待审核、未启用状态的旧稿，再写入 13 条审核修订记录）。
随后 41 把这 13 条审核激活并补 6 条高频症状（合计 19 条），42 完成疾病规则口径审核（9 条 approved、7 条生效），43 做激活后验收；
即使用户漏跑 21，41 也会先清掉 3 类旧稿残留再按审核文本重写，结果一致。
接着按 45 → 44 → 46 的顺序合入 v21 基线：45 落 DISH-121..170 共 50 道普通菜与 4 条新食材，44 把 3 条带进的未核查食材落定，46 生成 43 条 `-LS` 少盐变体；此时为 213 道。
再跑 47 → 49 → 53 → 54（dish_meta 配餐结构、烤/空气炸与坚果入菜、白名单增补 13 道、混合坚果），菜式到 222 道（179 普通菜 + 43 `-LS`）；其后执行 61 做法步骤补录：`core.dish` 增 `steps text[]`，222 道全部补到 2~3 条，`-LS` 与基础菜只差精盐克数，即食/水果统一「直接食用 / 按包装即食」，脚本二跑 0 更新。
222 道齐了再跑 04 整体验收与 22 补充验收（两份脚本的总数断言已改为 222 / 179 / 132 / 103 口径）。

## Docker 复跑

Docker 初始化流程在原有链路上增加 45 步执行 38 菜式扩充、46 步执行 39 过敏原复核、59 步执行 41/42/43 审核激活与验收、59v 执行 v21 合入（38→39→45→44→46，到 213 道）、59w 执行 222 落库（47→49→53→54→61）、59x 执行营养与档案收口（40→55→56→57→58→59）、59y 执行 63（给 `app.meal_plan` 加 `nutrition_tips` 列），并更新 60 汇总验收口径（dish=222、dish_nLS=179、steps=222、首批纤维钙菜式=60、未核查食材=0、反向营养 19 条已启用、疾病规则 9 条 approved / 7 条生效）。

**213 道与 222 道两步已挂入 initdb**：`docker/initdb/59v_v21_merge.sh` 在 59 之后、60 验收之前依次执行 38（菜式扩充 60→120，必须在 45 之前，45 的前置断言要求普通菜已达 120）→ 39（过敏原复核）→ 45（v21 50 道合入）→ 44（新食材落定）→ 46（43 条少盐变体），到 213 道；`docker/initdb/59w_rollout_222.sh` 紧接着执行 47 → 49 → 53 → 54 → 61，到 222 道；`docker/initdb/59x_nutrition_finalize.sh` 再执行 40 → 55 → 56 → 57 → 58 → 59，把维生素 A 补到 0 缺失、白米饭 65g、档案字段收口；`docker/initdb/59y_nutrition_tips.sh` 在 59x 之后执行 63，把 `nutrition_tips` 列落到 `app.meal_plan`。60 步的 04 验收按 222 口径（179 普通菜 + 43 少盐变体）判定。演练命令：`docker compose up -d --force-recreate`（需先删除 `pgdata` 卷），完成后 `docker compose logs db` 中应看到 `dish_total=213`（59v）与 `dish_total=222 / dish_nLS=179 / dish_LS=43 / dish_steps=222`（59w）。
