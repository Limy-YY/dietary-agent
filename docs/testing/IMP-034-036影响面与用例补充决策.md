**新增风险点（评估四项）**

1. **范围自由化后无边界约束**：`_resolve_gen_params` 不限跨度上限，理论上「配一年」会构造 365 天请求直打后端。离线断言只验解析正确，**跨度上限属产品决策缺口**，测试侧记录为观察项（不判缺陷，等 PM 定上限后补断言）。
2. **LLM 编排循环有轮次上限 6**：耗尽后静默走叙事层，用户侧看不到「未能完成」的信号。可接受（有兜底文案），但**多步任务失败时无法与成功区分**，LIVE 用例 L-01~03 即为盯此点。
3. **软偏好是降权非硬删**：`soft_avoid` 命中菜名只扣分，方案里仍可能出现炸物 → L-03 判据设计为「占比下降」，命中记 WARN 不判 FAIL，避免把产品设计当缺陷。
4. **IMP-036 依赖数据**：`core.symptom_nutrient_map` 由数据岗 D3 补数，表空时回落关键词兜底。测试只断言「方法标注与实际路径一致」，**不把表空判失败**。

## 3. 用例补充决策

**决策：xlsx 不重生成，增量挂门禁。**

- 理由一：116 条用例冻结在 v1.2 需求基线，重生成会丢失 11-14 以来的人工标注（BUG-06~13 处置、C-xx 结论）。

- 理由三：团队节奏是日更，门禁可随 commit 复跑，xlsx 做不到。
