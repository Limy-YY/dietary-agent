## 一、结论

**一句话**：能测的全测了，跑不了的卡在环境；已经发现的问题够开发改一轮，而且改起来都很便宜。

三点判断：

1. **数值口径已按任务书 v1.2 / 契约 §0.2 定案**（能量 = BMR × 1.4，不做缺口，`activity_level` 已删除），离线断言已同步：D1 期望 1839.6、`u_test_001` 期望 1734.6、D5 期望 1521.1，G1 组 11 项全部 PASS。v1.1 的「PAL 四档 + 减脂 −500」口径（1340 / 1482）作废，相关文档与用例已改写。
2. **工具层代码逻辑经桩测稳定**：12 个工具的 URL、方法、入参拼装、错误降级分支（业务错误码 / 断连 / 502 HTML）均正确。但这是把 `requests` 换成假对象跑出来的，**真实后端一次都没连过**，接口字段是否真如封装预期，未验证。
3. **模型层有真问题**：系统指令缺 4 处需求约束，其中 3 处直接对应验收关键检查点（R-01 油盐分级、R-04 双口径、R-07 就医提示）。这不是"代码写错了"，是"该说的话没写进指令里"——模型答得对不对全凭运气。这一条是**静态可判定的**，与是否有环境无关。

## 三、缺陷

### P1（高，阻断验收关键检查点）4 条

| ID | 标题 | 需求条款 | 影响 |
|---|---|---|---|
| BUG-01 | 系统指令缺 FR-21 油盐分级约束 | FR-21 / R-01 | 模型可能输出"用油 9.7g"这类需求明令禁止的伪精确值 |
| BUG-02 | 系统指令缺「非确定性措辞 + 强制就医提示」 | FR-29、FR-30 / R-07、5.2 第 4 组 | R-07 的两个关键检查点全靠模型随机性，验收无法保证 |
| BUG-03 | README 称指令含「双口径」，实际缺失 | FR-19~21 / R-04 | 食材口径与菜式口径混淆，用户看到的"热量"含义不明；且文档与代码不一致 |
| BUG-04 | 系统指令缺三餐 30/40/30 与供能比约束 | FR-13 / R-01 | 分配比例无保障，模型复述时易漂移 |

> 四条的共同点：**都只需要在 `agent.py` 的 `INSTRUCTIONS` 里补 1~2 句，成本约 10 分钟**，但对应的是验收表里 4 个关键检查点。建议优先改这个。

### P2（中）5 条

| ID | 标题 | 影响 |
|---|---|---|
| BUG-05 | `u_test_001` 能量目标口径冲突（1920 / 1482 / 1734.6） | **已定案（2026-11-14）**：PM 定口径按任务书 v1.2（BMR×1.4、无缺口），API-03 实测 1734.6 与口径一致；测试计划、用例、断言已同步，缺陷关闭 |
| BUG-06 | 自动 user_id 用秒级时间戳，同秒会覆盖 | 已稳定复现：连续两次建档都得到 `u_20261023172358` |
| BUG-07 | 空 user_id 未拦截，拼出 `/api/users//profile` | 打无效请求到后端，错误信息对用户不可读 |
| BUG-11 | HTTP 超时硬编码 30s，不区分接口 | 需求 3.3 是分级的（500ms / 3s / 15s），当前慢接口要拖满 30s 才降级 |
| BUG-12 | `generate_meal_plan` 必填日期，指令没定缺省规则 | 用户说"帮我配三餐"时，模型可能传空日期触发 422 |

### P3（低）4 条

| ID | 标题 |
|---|---|
| BUG-08 | 后端响应包装 `{code,message,data}` 未写进 SRS，裸 JSON 会被客户端误判为错误 |
| BUG-09 | `.env` 解析不处理引号与行尾注释，且覆盖系统环境变量（CI 场景会踩） |
| BUG-10 | `list_condition_rules` / `list_production_rules` 缺入参说明 |
| BUG-13 | `_smoke_test.py` 只 print 不 assert，回归时仍需人工看输出 |

完整复现步骤、证据与修复建议见工作簿 `03_缺陷清单`（含筛选与按级别取色）。

## 四、阻塞与恢复条件

| 阻塞原因 | 实测证据 | 影响用例 |
|---|---|---|
| 后端不在本机 | `127.0.0.1:8000/8080/9000/3000` 均无监听；直连返回 `000` | 全部 L4 端到端 |
| 无后端地址 | 交付包内无任何 IP/域名记录，无 `.env`；`E:\RG` 下只有 Agent 层代码 | 同上 |
| 无 LLM key | 只有 `.env.example` 模板 | 无法启动 Agent |
| `agno` 未安装 | `ImportError: No module named 'agno'`（`requirements.txt` 要求 `agno==2.8.7`） | `main.py` 无法启动 |
| 无前端 | 未提供 | 20 条 BLOCKED（UI / 兼容 / 部分安全） |

**恢复测试需要 4 样东西**：① 后端地址（`/api/health` 可达）② 一个 DeepSeek key ③ 前端地址 ④ 数据库只读账号。

拿到后写 `E:\RG\agent_1\.env`：

```
DEEPSEEK_API_KEY=sk-xxxx
DEEPSEEK_MODEL=deepseek-v4-flash
BACKEND_BASE_URL=http://<后端IP>:8000
```
