# Agent数据能力说明

这份文件主要告诉后端和Agent开发：数据库现在能提供什么。接口地址、鉴权和JSON格式由后端来定。

Agent建议通过后端工具访问数据库，不要直接连接数据库超级用户。

## 现有能力

| 能力 | 数据库对象 | 说明 |
|---|---|---|
| 搜索食材 | `app.search_ingredients` | 支持名称和别名，例如“西红柿”能找到“番茄” |
| 查询菜式营养 | `app.v_dish_live_nutrition` | 返回能量、蛋白质、钠、钙及完整性状态 |
| 过敏原筛查 | `app.screen_dishes_for_allergens` | 区分可用、明确排除和待核查 |
| 匹配营养参考值 | `app.match_nutrient_reference` | 按性别、年龄、生命阶段和月经状态匹配 |
| 每周UL评估 | `app.evaluate_weekly_ul` | 按每日最大值和超限天数判断 |
| 查看疾病规则目录 | `app.v_condition_rule_catalog` | 已有4条结构化高血压规则，可查看审核状态和来源 |
| 查询正式疾病规则 | `app.v_production_condition_rules` | 只返回审核通过并启用的规则，目前为0条 |
| 执行正式疾病规则 | `app.evaluate_daily_condition_nutrient_rule` | 已有生产保护，未审核规则不会返回正式结果 |

食材数据已经更新到2026-10-22版本。128种食材都有碘值和嘌呤等级，数据质量和逐条来源也已保留。后端封装食材详情接口时，可以从 `core.ingredient.micro_nutrients` 读取 `iodine_ug`，从 `purine_level` 读取嘌呤等级。

## 几个状态怎么处理

### 过敏原

- `eligible`：已核查，没有命中用户过敏原。
- `strict_exclude`：明确命中过敏原，不能推荐。
- `exclude_until_verified`：有配料没核查，确认前先排除。

“未核查”不能写成“安全”。

### 营养参考值

返回 `needs_clarification = true` 时，需要继续问用户，不能随便选一个值。

### 营养数据缺失

完整性字段为 `false` 时，不能把空值当成0，也不能直接判断达标。

### 疾病规则

4条高血压规则已经完成结构化入库、来源关联和审核状态管理，包括三个钠目标及DASH饮食模式。

因为不同目标适用条件不同，这些规则当前处于“已入库、待专业审核”状态。正式规则数量为0，表示暂时没有规则进入生产自动判断，并不是没有规则数据。审核通过并启用后，Agent才可以通过正式接口使用。

## 后端可以封装的工具

- 搜索食材；
- 查询菜式营养；
- 按过敏原筛菜；
- 匹配RNI/AI/UL；
- 汇总每日或每周营养；
- 查看待审核疾病规则及来源；
- 查询已经审核的疾病规则。

接口返回时最好带上数据完整性、来源ID和是否需要人工确认。具体接口路径和JSON结构由后端与Agent开发一起确定。
