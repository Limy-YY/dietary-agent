# 膳食搭配智能体：应用查询与验收报告

## 1. 执行结论

第五步已完成。数据库新增 2 个只读视图、5 个查询或辅助函数，并使用正式层真实数据完成验收。脚本重复执行通过，`app` 业务表仍为 0 行，没有生成用户、膳食计划、计算结果或对话数据。

## 2. 新增应用接口

| 对象 | 用途 |
|---|---|
| `app.v_ingredient_search` | 提供食材名称、别名、营养值、过敏原和来源的统一搜索数据 |
| `app.v_dish_live_nutrition` | 按当前食材事实表实时汇总菜谱营养与过敏原 |
| `app.search_ingredients(query, limit)` | 按名称或别名进行精确、前缀和包含搜索 |
| `app.screen_dishes_for_allergens(allergens)` | 返回严格排除、待核查或可用三种结果 |
| `app.match_nutrient_reference(...)` | 按性别、月龄、生命阶段和月经状态匹配 RNI/AI/UL |
| `app.evaluate_weekly_ul(...)` | 按每日摄入量计算每日最大值和超限天数 |
| `app.age_in_months(birth_date, as_of_date)` | 由出生日期计算完整月龄 |

`app.profile` 新增可选字段 `birth_date`。原有 `age` 字段保留，用于兼容或展示；涉及婴幼儿和年龄边界的参考值匹配应优先使用出生日期计算月龄。

## 3. 验收结果

### 食材搜索

- 使用别名“西红柿”搜索，正确返回 `CN-405 番茄`。
- 匹配类型为 `alias_exact`。
- 缺失营养值仍返回 `NULL`，不会显示为 0。

### 过敏原筛选

以“鸡蛋”为用户过敏原测试 30 道菜：

- `strict_exclude`：3 道，配料已确认含鸡蛋。
- `exclude_until_verified`：3 道，存在未核查配料。
- `eligible`：24 道，已核查且未命中鸡蛋。

筛选逻辑没有把空过敏原列表直接解释为安全。第五步抽样时还发现椰子油的 `allergens` 是 JSON 数组，而其他食材为分号文本；转换脚本已兼容两种表示，正式层现正确保存为“树坚果”。

### 菜谱营养

- 实时营养视图返回 30 道菜。
- 与正式菜谱营养快照进行独立比较，差异数为 0。
- 热量、蛋白质或钠存在缺失来源时，对应菜谱汇总保持 `NULL`。

### RNI 人群匹配

- 男性 30 岁：返回 18 种营养素，没有歧义。
- 女性 55 岁、未提供月经状态：铁返回 2 个候选值，分别为 10 mg 和 12 mg，`needs_clarification=true`。
- 女性 55 岁、月经状态为“有月经”：只返回 12 mg，歧义消失。
- 6 月龄正确匹配 `0-6月`，7 月龄正确切换到 `7-12月`。
- 孕中期女性返回 18 种营养素，没有歧义。
- 出生日期 `2026-03-15` 在评价日期 `2026-10-15` 的计算结果为 7 月龄；未来出生日期返回 `NULL`。

### 周报 UL 判断

钙的三日测试数据为 1000、2500、1800 mg：

- 周总量：5300 mg，仅用于展示。
- 日均值：1766.6667 mg。
- 每日最大值：2500 mg。
- 每日 UL：2000 mg。
- 超限天数：1 天。
- 结果：`over_ul`。

该结果证明系统使用每日值判断 UL，没有把 5300 mg 周总量直接与 2000 mg 每日 UL 比较。钠在当前参考数据中没有 UL，函数返回 `ul_not_available`，不会自行构造上限。

## 4. 当前限制

1. 食材量只有 128 条，名称和别名包含搜索已足够；数据规模增大后可再评估中文分词或专用检索索引。
2. 知识文档尚无向量列，需先确定嵌入模型和向量维度。
3. 四项非阻断数据缺口仍保留，包括部分食材营养值、两条婴儿膳食纤维参考值和 8 个知识库专有营养素的单位。
4. 视图和函数已经可供后端调用，但还没有应用账号权限、接口层或前端页面。

## 5. 下一步建议

第六步可以建立最小测试用户和一份测试餐单，仅使用虚构数据，验证 `profile → meal_plan → nutrition_result → weekly_nutrition_report` 的完整业务链路。测试通过后再决定应用接口和真实用户数据接入方式。
