# 数据库交付说明

数据库名称：`diet_agent`  
版本：V1.2（60道菜最终版）  
更新日期：2026-11-13

## 这份交付包是什么

这份交付包只包含一个数据库版本，即当前最新的V1.2完整数据库，不包含30道菜的旧备份，也不包含增量更新脚本。

数据库中目前有：

- 128种食材；
- 60道菜；
- 254条菜式与食材关系；
- 5类健康目标结构映射；
- 7种关键微量营养素；
- 用户档案、食材池、计划、餐位、候选、购物清单、营养报告、对话引用和调整记录等V1.2数据结构。

## 后端怎么恢复

1. 准备PostgreSQL 18或兼容版本。
2. 新建一个名为 `diet_agent` 的空数据库。
3. 使用 `01_完整数据库备份_diet_agent_v1.2_60道菜.dump` 恢复数据库。
4. 需要使用项目统一权限组时，由数据库管理员运行 `03_应用账号与权限.sql`。
5. 运行 `04_数据库整体验收.sql`，确认恢复结果。

命令示例：

```bash
createdb diet_agent
pg_restore --no-owner --no-privileges -d diet_agent 01_完整数据库备份_diet_agent_v1.2_60道菜.dump
psql -d diet_agent -f 03_应用账号与权限.sql
psql -d diet_agent -f 04_数据库整体验收.sql
```

如果后端使用Docker或远程数据库，需要自行补充实际的主机地址、端口、账号和密码。

## 数据说明

新增的30道家常菜参考国家卫生健康委公开食养指南，并按项目现有食材池和单人份口径做了标准化。指南未给出单道菜油盐量的部分标记为估算值，营养结果根据食材成分和使用克数计算。

绿豆芽和燕麦片的过敏原状态仍为“未核查”。这表示对应食材还需要继续核对，不表示已经确认含有过敏原。候选生成时应保留该提示。

数据库完成的是数据存储和约束。候选生成、目标计算、意图识别和Agent调用仍由后端及规则引擎完成。
