## 三、鉴权

接口无登录端点，token 由 `JWT_SECRET` 离线签发（`app/core/security.py: create_access_token`）：

```bash
cd backend
.venv/Scripts/python -c "from app.core.security import create_access_token; print(create_access_token('TEST-E2E-01', 1440))"
```

所有业务接口带 `Authorization: Bearer <token>`；不带返回 401。

## 四、三写落库：谁写、写到哪、怎么验

代码核查结论（`grep INSERT / db.add / commit` 全仓）：写库只发生在 `backend/app/routers/`，
`services/rule_engine/` 内没有 INSERT、`db.add` 或 `commit`，它只计算、不落库；Agent 侧也不直连库，
唯一的档案写是 `bc.upsert_profile` 走 REST 回后端。

| 写 | 接口 | 代码位置 | 落库表 |
| --- | --- | --- | --- |
| 档案写 | `PUT /api/profile`（`POST /api/profile` 同义） | `routers/profile.py:174` INSERT + `:210` commit | `app.profile` |
| 方案写 | `POST /api/meal-plan/week/generate` | `routers/mealplan.py:315` → `_persist_plan()`（`:220`）：`:229` MealPlan、`:254` db.add、`:265` meal_slot、`:295` meal_candidate_dish、`:358` commit | `app.meal_plan` / `app.meal_slot` / `app.meal_candidate` / `app.meal_candidate_dish` |
| 对话写 | `POST /api/agent/chat`（SSE 流式） | `routers/chat.py:78` INSERT conversation、`:93` `_save_message()` INSERT message（`:199` 用户、`:271` 助手）、`:83` / `:98` commit | `app.conversation` / `app.message` |

衍生写（同一批路由，不属于三写主线，但会改库）：

| 接口 | 表 |
| --- | --- |
| `POST /api/meal-plan/candidate/swap` | `app.plan_adjustment`（`mealplan.py:420`） |
| `POST /api/meal-plan/week/fix` | 更新 `app.meal_plan` 状态（`mealplan.py:358`） |
| `POST /api/nutrition/analysis` | `app.nutrition_report` / `app.nutrition_report_plan`（`nutrition.py:610` / `:634`） |

### 可验证判据（本次实测，2026-11-16）

| 写 | 操作 | 库内结果 |
| --- | --- | --- |
| 档案 | `PUT /api/profile`（`gender=女, age=26, 160cm, 55kg, goal_code=digestive_health`） | 200；`app.profile` 出现 `TEST-E2E-01`，`target_calories=1762.6`（=BMR×1.4 后端算好落库） |
| 方案 | `POST /api/meal-plan/week/generate`（`2026-11-17`，早午晚） | 200；`meal_plan_id=10`、`status=candidates`、`goal_energy_kcal=1762.6`；`meal_slot=3`、`meal_candidate=9`（每餐 3 个）、`meal_candidate_dish=27` |
| 对话 | `POST /api/agent/chat`（"中午吃什么比较好"） | 200（SSE）；`conversation_id=1`；`app.conversation=1`、`app.message=2`（user + assistant 各一条，流结束时整段写入） |

核对 SQL：

```sql
SELECT user_id, target_calories FROM app.profile WHERE user_id = 'TEST-E2E-01';
SELECT meal_plan_id, plan_type, status, goal_energy_kcal FROM app.meal_plan WHERE user_id = 'TEST-E2E-01';
SELECT count(*) FROM app.meal_slot s WHERE s.meal_plan_id = 10;        -- 3
SELECT count(*) FROM app.message m JOIN app.conversation c USING (conversation_id) WHERE c.user_id = 'TEST-E2E-01';  -- 2
```

注意：对话在 Agent 服务不可达时**仍会落库**（会话与消息照写，SSE 回一条"Agent 不可达"提示），
所以"库里有 message"不代表 Agent 链路通了，判定 Agent 链路要看 SSE 正文。

## 五、启动与停止

```bash
# 库
cd docker && docker compose up -d          # 或 docker start diet-agent-db

# 后端（工作目录必须是仓库的 backend/，venv 复用 ../../backend/.venv）
cd backend
"../.venv/Scripts/python" -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 公网隧道
cloudflared tunnel --url http://localhost:8000
```

`backend/.env` 的 `DATABASE_URL` 用 `diet_backend`，`APP_HOST=127.0.0.1` 只影响应用自读配置，
实际监听地址由命令行 `--host` 决定。
