# 数据库验收执行说明（QA-04）

> 维护：测试岗 · 马英慧 ｜ 响应数据岗 2026-11-13 日志求助（缺 pg_restore 18 + pgvector 环境）
> 目标：任何成员本机一条命令起库，复现 v1.2（60 道菜）整体验收，与数据岗 `05_数据库整体验收结果.txt` 对齐。

## 一、前置条件

- 已安装 Docker Desktop（Windows：需 WSL2 后端）。
- 仓库根目录下 `database/` 交付包齐全，先校验完整性：

```bash
cd database
sha256sum -c 09_文件校验值.sha256
```

任何一行 FAIL 都要停下找数据岗重传，不要带伤还原。

## 二、一键起库（自动还原）

```bash
cd deploy
docker compose up -d
```

首次启动会自动依次执行（见 `db_init/01_restore.sh`）：

1. `CREATE EXTENSION vector`（失败不阻塞，向量接线是后续里程碑）；
2. `pg_restore` 还原 `database/01_完整数据库备份_diet_agent_v1.2_60道菜.dump`；
3. 应用 `database/03_应用账号与权限.sql`。

健康检查通过（`docker compose ps` 显示 healthy）即还原完成。

**重置重来**：`docker compose down -v && docker compose up -d`（-v 删数据卷，dump 会重新还原，幂等）。

## 三、跑整体验收（04 脚本）

```bash
docker exec -it diet-agent-db psql -U diet_app -d diet_agent -f /delivery/04_数据库整体验收.sql \
  | tee 04_验收_本机结果.txt
```

判定标准：

- 脚本以 `\set ON_ERROR_STOP on` 运行，**任何断言失败会中途退出、退出码非 0**；
- 逐段比对输出与 `database/05_数据库整体验收结果.txt`：表结构断言、基础数据计数（128 食材 / 60 菜 / 254 菜式食材关系 / 5 目标映射 / 7 关键微量）、计划流程、60 道菜明细逐行一致；
- 全部一致 → 记 **27/27 通过**；有差异 → 截图差异行报数据岗，不要自行改库。

## 四、手工路径（不用 compose 时）

```bash
createdb -U diet_app diet_agent
pg_restore --no-owner --no-privileges -d diet_agent database/01_完整数据库备份_diet_agent_v1.2_60道菜.dump
psql -U diet_agent -d diet_agent -f database/03_应用账号与权限.sql
psql -U diet_app -d diet_agent -f database/04_数据库整体验收.sql
```

要求 PostgreSQL 18 或兼容版本；`pg_restore` 版本需 ≥ dump 生成版本，否则报「unsupported version in file」。

## 五、与后端联调

- compose 暴露 `5432`，连接串：`postgresql://diet_app:diet_app_dev@localhost:5432/diet_agent`；
- 该账号密码**仅限本地验收**，正式部署前必须更换并走 03 脚本的权限组；
- 后端 `backend/` 的数据库配置指向本容器即可，无需各自装 PG。

## 六、已知边界

- `pgvector` 扩展：向量检索接线（里程碑 5.2.6）之前不是验收项，镜像不支持也不影响 27 项判定；
- 数据岗待补数据（铁源 `rni_reference.json` 两行、纤维 60/60、钙 43/60）到位后会重灌，届时基线计数以新交付说明为准，本说明同步更新；
- 绿豆芽、燕麦片过敏原为「未核查」，是数据状态不是缺陷，验收时不得改为已核查。
